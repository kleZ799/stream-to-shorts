Stream to Shorts runs on a Mac now. That is the whole release — and the mac half is a beta that has never been run on a Mac.

## There is a Mac build

`StreamToShorts-macOS-arm64.zip` — 165 MB, Apple Silicon, ffmpeg bundled, nothing to install. Unzip it and drag it to Applications.

It is the same app doing the same work: paste a URL or drag a video in, describe the layout in words, get vertical clips back. Same ranking, same layouts, same editing, same pause button.

## Read this before you download it

**Nobody has ever opened it.** I develop on Windows and do not own a Mac. PyInstaller cannot cross-compile, so the mac app is built and checked entirely by GitHub's macOS runners — the build is signed, the version is verified, the bundled ffmpeg is confirmed to run — and then published without a human ever double-clicking it.

So it might not start. If it doesn't, that is a bug here and not something you did wrong, and I would genuinely like to hear about it. Two things help:

- `~/Movies/StreamToShorts/app.log` — startup errors are written here, including ones the app has no window to show you in.
- Running it from Terminal so errors print where you can see them:
  ```
  /Applications/StreamToShorts.app/Contents/MacOS/StreamToShorts
  ```

[Open an issue](https://github.com/kleZ799/stream-to-shorts/issues/new) with either of those and your macOS version. With no Mac here to reproduce on, a pasted error is the whole difference between fixed and guessed at.

**Windows is the tested build.** If you have both machines, use that one.

## macOS will refuse to open it the first time

This part is normal and is not the beta — it happens to every unsigned app.

1. Double-click it. macOS says it is damaged, or that Apple cannot check it for malware. Let it refuse.
2. **System Settings → Privacy & Security**, scroll down, **Open Anyway**, confirm.
3. It opens normally every time after that.

Right-click → Open, the old shortcut for this, stopped working in macOS 15.

The app is signed, but not by Apple: notarising costs $99 a year and this project does not take money. Gatekeeper is reporting a missing Apple signature, not a finding about the file.

## Two things that differ from Windows

**Transcription runs on the CPU.** No Mac has an NVIDIA card, and the transcription engine has no Metal backend, so an M-series CPU does all of it. It works; a long VOD takes a while.

**It does not update itself.** A `.app` is hundreds of files signed as one unit, and replacing that under a running process leaves a signature that no longer matches its contents — the app macOS would then refuse to open is the one the update was delivering. So the mac app tells you a new version is out and you download it. The Windows build still updates itself as before.

Files also land in mac places: `~/Movies/StreamToShorts` for clips, `~/Library/Application Support/StreamToShorts` for settings.

## Nothing changed for Windows

No behaviour changes on Windows in this release. The exe is rebuilt from the same code and updates itself as usual.
