The install instructions now travel with the download.

## Nothing in the app changed

If you are on v1.10.0 this alters only what is in the archive around it. There
is no reason to hurry, and the Windows build is byte-for-byte the same program.

## The mac zip unpacks to a folder

`StreamToShorts.app`, and `READ ME FIRST.txt` beside it: installing it, the
first launch macOS is going to refuse and how to get past that, where the clips
land, what runs differently from the Windows build, and how to report it when
it does not start.

That build has a first launch that is *supposed* to fail. Being told so
beforehand is the difference between a Gatekeeper dialog and a deleted
download — and a README on a web page is not there six months later when
somebody finds the zip in their Downloads folder and tries again.

## Linux gets the same thing as a second file

`StreamToShorts-linux-README.txt`, published beside the binary rather than
wrapped around it. The app updates itself by downloading that binary and
swapping it into place, so it has to stay exactly a binary — putting it inside
a tarball would mean teaching the update path to unwrap one, on every future
release, to solve what a second file solves for nothing.

It covers the thing most likely to catch someone out. **`libGL.so.1` is not in
the box.** OpenCV wants it for the face tracking, every desktop already has it,
and a headless machine wants `sudo apt install libgl1` (or
`dnf install mesa-libGL`) first. It is not bundled because a graphics library
belongs to your machine's own driver stack; shipping one would be shipping the
wrong one.

Without it the app starts, serves and downloads perfectly well, and then fails
at the moment it first looks for a face — which is a confusing place to find
out.

---

**StreamToShorts.exe** — 219 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**StreamToShorts-linux-x86_64** — 278 MB, x86-64, self-contained, glibc 2.35 or
newer. `chmod +x` it and run it. **Still untested on a desktop distribution** —
it is built and exercised under WSL, and every published build is started by
the release workflow and asked for its interface before the release exists, but
nobody has yet sat at Fedora and made a Short with it. Take
`StreamToShorts-linux-README.txt` too.

**StreamToShorts-macOS-arm64.zip** — 165 MB, Apple Silicon only. **Still a
beta, and still has never been run on a Mac** — I do not own one, so it is
built and checked by GitHub's macOS runners and published without a human
opening it. If it does not start, that is a bug here:
`~/Movies/StreamToShorts/app.log` and
[an issue](https://github.com/kleZ799/stream-to-shorts/issues/new) are how it
gets fixed.

On v1.5.0 or later on Windows, or on any Linux build? The app will offer this
to you.
