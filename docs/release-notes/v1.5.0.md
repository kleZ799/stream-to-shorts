From here the app updates itself. Every build before this one — 1.4.0 included — was compiled before the updater existed, so those copies cannot be told about anything new. Install this one, and that stops being true.

## It updates itself

The app checks GitHub at launch, again every half hour while it is open, and whenever you come back to the window after being away. Publish a build at noon and someone who opened the app at nine hears about it in the session they are already in, without restarting.

When there is something new, a banner offers to install it. Pressing the button downloads the new build, checks it against the SHA-256 that GitHub reports, replaces the running exe in place, and reopens on the new version. Same folder, same filename, nothing to move.

The replaced build is deleted, not left behind. That sounds obvious and the first attempt got it wrong: the old exe is still shutting down and still holding its own file when the new one starts, so the delete failed silently and 229 MB stayed on disk until the app happened to be launched a second time. It now retries until the handover completes, and sweeps abandoned part-downloads at the same time.

Nothing is touched until the checksum matches, so a failed or interrupted download leaves the working app exactly as it was.

There is a **Check for updates** button in the top bar and a row in the sidebar, for when you would rather ask than wait.

## You can see what you are running

The version now sits in the top bar beside the name, on the launch card, and under the sidebar. It comes from the app itself rather than the update check, so it is there with no internet — which is usually when someone needs to tell you what version they are on.

The README shows the current release under the download button, read live from GitHub, so it can never disagree with what is actually published.
