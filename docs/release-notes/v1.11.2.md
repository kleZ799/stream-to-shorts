A small one: the app now tells the truth about how long "follow my face" takes.

## An honest warning

Picking the face-following layout shows a warning before you commit to a long
render. It said that mode was about twenty times slower than the others,
because it used to look for a face on every single frame. Since v1.11.0 it
plans a smooth camera move instead, and it was re-measured: about **nine times**
slower than a plain crop — a minute and a half for a 30-second clip from a 720p
stream, more at 1440p. The warning now says that.

Nothing else in the app changed. The documentation did: the README, the
walkthrough and the concepts guide all describe what v1.11 actually does now —
titles written from what is on screen, ranked title options, the webcam panel
cropped inside your overlay, the smooth face crop, and runs that retry
themselves — with every screenshot retaken on the current build.

---

**StreamToShorts.exe** — about 220 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**StreamToShorts-linux-x86_64** — about 278 MB, x86-64, self-contained, glibc
2.35 or newer. `chmod +x` it and run it. **Still untested on a desktop
distribution** — every published build is started by the release workflow and
asked for its interface before the release exists, but nobody has yet sat at
Fedora and made a Short with it. Take `StreamToShorts-linux-README.txt` too.

**StreamToShorts-macOS-arm64.zip** — about 165 MB, Apple Silicon only. **Still
a beta, and still has never been run on a Mac** — I do not own one, so it is
built and checked by GitHub's macOS runners and published without a human
opening it. If it does not start, that is a bug here:
`~/Movies/StreamToShorts/app.log` and
[an issue](https://github.com/kleZ799/stream-to-shorts/issues/new) are how it
gets fixed.

On v1.5.0 or later on Windows, or on any Linux build? The app will offer this
to you.
