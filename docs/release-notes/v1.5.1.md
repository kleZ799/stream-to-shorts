**The app is unchanged from v1.5.0.** This release exists to prove two things that had only been tested in pieces.

## Built by CI, not by a laptop

Every release before this one was produced by running PyInstaller on a development machine, which meant a release depended on that machine being awake, the app being closed, and nothing else holding a file open in the build directory. Two of today's builds failed for exactly those reasons.

This exe was built on a clean GitHub runner from the tagged commit, with its own freshly downloaded ffmpeg. Nothing about the machine it was built on can leak into it, and the build refuses to run at all if the tag and the version compiled into the app disagree — a mismatch there would offer every user an update to the version they already have, on a loop.

## The first real update

v1.5.0 was the first build that could update itself, but nothing had ever actually updated *to* anything — the mechanism was tested part by part, never end to end against a real release.

This is that release. If you are on v1.5.0, your app should notice this build on its own, offer it, download it, check it against the SHA-256 published here, replace itself, and reopen on v1.5.1.

If it does, updates work. If it does not, that is worth telling me about on [Discord](https://discord.gg/jnMrGbBz3m) — knowing the update path is broken matters more than any feature in it.

**StreamToShorts.exe** — 229 MB, Windows, self-contained, ffmpeg bundled. Unsigned, so SmartScreen will warn: **More info → Run anyway**.

On v1.5.0 already? Do nothing. The app should offer this to you.

On anything older? This one is a manual download, and the last one — every build before v1.5.0 was compiled before the updater existed and cannot be told about new versions.
